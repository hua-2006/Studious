## 三、本地 MT 专项（Sprint 1 + 2）

### 能力

| 方向 | 译文示例 | 耗时 |
|---|---|---|
| en→zh | 快速棕色狐狸跳过懒狗 | 373 ms |
| zh→en | It's a nice day. Let's go for a walk in the park. | 751 ms |
| en→ja | どう か , あなた の 定め を 堅 く 置 い て くださ い .（模型本身弱） | 437 ms |
| ja→en | Hey, wait a minute! | 237 ms |

- 直连优先；缺对时走英文中转（A→en→B）
- 模型 id 空间是 `vocab.json`（65001 项），spm 只负责切词/反分词 —— 这是最关键的一条
- KV cache（merged 模型）+ beam search（config 里的 num_beams）

### 关键取舍（实测）

| 配置 | 延迟 | 质量 |
|---|---|---|
| 非 cache + 贪心（Sprint 1） | 266 ms | 棕色狐狸跳过懒狗 |
| cache + 贪心 | 246 ms（**1.09x**） | 同上（逐 token 一致） |
| cache + beam=4 | 364 ms | **快速**棕色狐狸跳过懒狗 |

**KV cache 只快 1.1x 的原因已定位**：merged 模型每步 Run 有 ~22 ms 固定开销（ORT 对 control-flow 子图的执行成本，与 past 长度、线程数无关），把算法收益吃掉了。要真正吃到，需用 onnx 工具把 `If` 的 then 分支抽成独立图（当前环境无 python onnx，未做）。

## 二、架构

```
frontend/  Qt Widgets（测试 UI）
    │  纯文本 + 语言对
    ▼
backend/   纯翻译引擎（C++20 + Qt Core，平台无关）
    ├─ TranslatorRouter   选引擎 / 降级 / 缓存 / 同语言直返
    ├─ web                Google · MyMemory · Azure(占位)
    ├─ llm                云端（OpenAI 兼容）/ 本地 llama.cpp
    ├─ mock               离线自测
    ├─ local-mt           v2 占位
    ├─ asset              manifest 验签 · 下载 · 安装 · 删除
    ├─ cache              SQLite 翻译记忆
    └─ i18n               双语错误 + 语言检测
```

**边界铁律**：`backend/` 内不得出现 `windows.h` 等平台头文件（已 CI 式扫描验证为 0）。

## 五、本轮修复的问题清单

| # | 现象 | 根因 | 修法 |
|---|---|---|---|
| 1 | 译文 = 原文 | 小模型偷懒直接回吐 | 检测 + 重试 + 报错 |
| 2 | 复读刷屏（7.2 s、数千字） | 模型陷入循环 + max_tokens 过大 | 按输入封顶 + 截断 |
| 3 | 部分照抄（前半英文后半中文） | **中英混排 prompt 诱导复读** | 换纯英文 prompt + 字符集校验 |
| 4 | 目标中文却输出意大利语 | 模型跑偏 | 目标语种校验 + 重试 |
| 5 | 英→日 全失败 | **源语言未识别，prompt 没点明方向** | 语言检测（修后正常） |
| 6 | 碎片化输出 | 模型退化 | 单字符片段占比检测 |
| 7 | 纯数字/符号也发请求 | 无输入预检 | 预检直接返回 |

## 八、已知限制与风险

| 项 | 说明 |
|---|---|
| 拉丁语系内部 | 字符集校验无法区分英/法/德/西/意，只能靠停用词检测 |
| 短句 | <3 个词时检测置信度低，可能不指定源语言 |
| 1.5B 英→日 | 质量仍不稳定（0.5B 现已可用） |
| MT（v2） | 成对模型无自纠能力，**源语言选错必出垃圾**，届时须强制检测 |
| 前端 i18n | 仅资产模块双语，主窗口仍硬编码中文 |
| 密钥 | `TrustKeys.h` 是开发公钥，发版前必须换钥 |
